# Інвентаризація ПЗ: n8n + Claude

Читає вивід `winget list`, зводить пакети до продуктів і розкладає їх по категоріях.

Класифікує Claude, але тільки те, чого ще немає в довіднику. Повторний прогін того самого файлу коштує **0 запитів до AI**.

```
winget list  →  розбір  →  довідник  →  Claude (тільки нове)  →  довідник + звіт
```

## Що всередині

| Файл | Призначення |
|---|---|
| `Software inventory → catalog (Claude).json` | Основний workflow: форма, розбір, класифікація, запис у довідники |
| `Software inventory — setup (run once).json` | Установник: створює 4 таблиці й наповнює їх категоріями та базовими правилами |

API-ключів у файлах немає — n8n ніколи не вивантажує секрети. Свій ключ ви додасте на кроці 2.

## Вимоги

- **n8n 2.x** — потрібна підтримка Data tables.
- **API-ключ Anthropic** з [console.anthropic.com](https://console.anthropic.com): `Settings → API keys → Create Key`.

> [!IMPORTANT]
> Підписка Claude Pro чи Max для API не працює. Це окремий рахунок: у розділі Billing мають бути кошти.

## Встановлення

### Крок 1. Імпортувати обидва workflow

У n8n: `Overview → Create workflow → ⋯ → Import from File`. Зробити двічі, для кожного файлу.

### Крок 2. Підключити Claude

1. `Credentials → Add credential → Anthropic API`.
2. Вставити свій ключ, дати ім'я, зберегти.
3. Відкрити workflow **Software inventory → catalog (Claude)**, знайти вузол **Claude classify** і в полі Credential вибрати щойно створені credentials.
4. Зберегти workflow.

### Крок 3. Створити таблиці

1. Відкрити workflow **Software inventory — setup (run once)**.
2. Натиснути **Execute workflow** внизу редактора — відкриється вкладка з формою.
3. Натиснути в ній **Submit**.

Вмикати цей workflow перемикачем Active не треба, це разова дія.

З'явиться «Tables are ready». Створяться `sw_categories`, `sw_software`, `sw_packages`, `sw_runs`. Запускати повторно безпечно: наявні дані не затираються.

### Крок 4. Увімкнути основний workflow

1. Увімкнути **Software inventory → catalog (Claude)** перемикачем **Active**.
2. У вузлі **Form** скопіювати **Production URL** — це робоча адреса форми.

## Використання

Зібрати перелік ПЗ у PowerShell на потрібному комп'ютері:

```powershell
winget list > software.txt
```

Кодування значення не має: розбір розуміє UTF-8, UTF-16 і BOM.

Відкрити адресу форми, завантажити `software.txt`, натиснути **Submit**. Для ~130 пакетів перший прогін триває кілька хвилин: усе невідоме йде до Claude одним запитом.

На екрані «Готово» буде підсумок і повний розподіл — категорія → продукт → його пакети:

```
Запуск run-20260922224744
Пакетів у файлі: 131
Нових пакетів: 0; оновлених: 126
Нового ПЗ: 0; викликів AI: 0
На ручну перевірку: 3

▐ Браузери — ПЗ: 3, пакетів: 6
   Google Chrome
   Microsoft Edge: Microsoft Edge, Microsoft Edge для Game Bar
   Mozilla Firefox: Mozilla Firefox (x64 uk), Mozilla Maintenance Service
```

### Перевірка, що все працює

Завантажити **той самий файл** ще раз. У підсумку має бути:

```
Нових пакетів: 0; оновлених: 0
Нового ПЗ: 0; викликів AI: 0
```

`викликів AI: 0` означає, що довідник працює і другий прогін безкоштовний.

## Як це влаштовано

**ПЗ** — це продукт, який людина свідомо встановлює або купує: Microsoft Office, Python, Mozilla Firefox.
**Пакет** — компонент або варіант встановлення цього продукту: Word, Python Launcher, Mozilla Maintenance Service, окремі копії x64 і x86.

Кілька пакетів мапляться на одне ПЗ, тож службові компоненти й оновлювачі не засмічують довідник:

```
Microsoft Word     ┐
Microsoft Excel    ├─→ Microsoft Office  →  Офіс і продуктивність
Microsoft Outlook  ┘
```

Порядок зіставлення для кожного пакета:

1. **Довідник** — пакет уже класифікований, береться готове рішення.
2. **Правило** — спрацював alias наявного ПЗ.
3. **Claude** — усе інше, пачкою до 150 пакетів за один запит.

Тому вартість несе лише перша зустріч з пакетом.

### Таблиці

| Таблиця | Що зберігає |
|---|---|
| `sw_categories` | Закритий список із 16 категорій |
| `sw_software` | Довідник продуктів: назва, вендор, категорія, правила зіставлення |
| `sw_packages` | Довідник пакетів: версія, джерело, прив'язка до ПЗ, впевненість |
| `sw_runs` | Журнал запусків зі статистикою |

**Кілька комп'ютерів.** Кожен новий файл лише доливає те, чого в довіднику ще немає. Дані попередніх машин не чіпаються. Чим більше файлів, тим менше роботи для AI: спільні програми вже класифіковані.

**Довідник не знає, на якій машині що стоїть.** Він відповідає на питання «що це за пакет і до якого продукту належить», а не «де встановлено». Поле `version` — версія з файлу, завантаженого останнім.

**Категорії — закритий список.** AI не може вигадати нову: схема відповіді технічно це забороняє. Саме тому результати стабільні. Додати категорію можна рядком у `sw_categories`.

## Ручні правки

Переживають усі наступні запуски:

| Що зробити | Де | Результат |
|---|---|---|
| `match_method = manual` + свій `software_key` | `sw_packages` | Пакет назавжди закріплений за цим ПЗ |
| `locked = true` | `sw_software` | AI не перезапише назву й категорію ПЗ |
| Дописати `aliases` | `sw_software` | Нове правило: пакети з таким префіксом ідуть до цього ПЗ без AI |

Формат `aliases` — `id:<початок package_id>` або `name:<початок назви>`, кілька правил через `|`, усе малими літерами:

```
id:microsoft.vcredist|name:microsoft visual c++ 20
```

## Якщо не працює

| Симптом | Причина |
|---|---|
| `401 invalid x-api-key` у підсумку | Ключ не вставлено або у вузлі **Claude classify** обрано не ті credentials |
| `Problem loading form` | Workflow вимкнений — увімкнути перемикач **Active** |
| Пакети щоразу йдуть до AI | Таблиці не створилися або порожні — запустити setup ще раз через **Execute workflow** |
| Правки у вузлах зникли | Вкладка редактора n8n була відкрита зі старим станом і перезаписала їх. Перед редагуванням оновлювати сторінку |

## Вартість

Платить лише перша зустріч з новим пакетом: один запит до Claude на файл, незалежно від кількості невідомих пакетів у ньому. Усе, що вже в довіднику, безкоштовне.

Модель — `claude-opus-5`, змінюється однією константою `MODEL` у вузлі **Match**.
